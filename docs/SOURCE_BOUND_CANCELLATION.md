# Source-bound cancellation sentences

The companion now contains two English sentences whose formal meanings have
been checked in the contexts of the actual Bézout proof. These are the two
applications of `mul_left_cancel₀` in
`OAI.ComplexCancellation.BezoutFrame.exists_frame`, at retained source frames
40 and 53. This is not a certification of either entire proof section or of the
whole companion.

## Checked text

The sentences are generated by the executable Lean renderer in
`lean/ArithmeticEnglish.lean`:

```text
Since g is nonzero and (g * ((a * r) + (d * s))) = (g * 1), cancel g to obtain ((a * r) + (d * s)) = 1.

Since g is nonzero and (g * (a * y)) = (g * (d * (z + 1))), cancel g to obtain (a * y) = (d * (z + 1)).
```

The parentheses preserve the arithmetic syntax. The renderer supports the finite
source variables `x`, `y`, `z`, `g`, `a`, `d`, `r`, and `s`, the constants zero and
one, and addition, multiplication, and subtraction. Unsupported expressions do
not receive an explanation.

The formal meaning of a sentence asserts all three facts: the factor is nonzero,
the multiplied expressions are equal, and the resulting expressions are equal.
It is not merely a conditional that becomes vacuously true when a premise is
false. The native certificate supplies the nonzero proof and equality proof from
the selected original application.

## Source correspondence

`lean/SourceCancellation.lean` follows each specified occurrence path in the
original theorem's elaborated proof. It opens only that occurrence's enclosing
binders and lets. A separate traversal and a structural expression comparison
check that the selected proof is the original subterm after metadata erasure.
A same-typed replacement proof is not accepted as the original proof.

The importer then:

1. Requires a fully applied `mul_left_cancel₀` node and extracts its arguments.
2. Assigns the displayed variable names to unique, correctly typed source-local
   variables. It reifies the actual scalar expressions into the arithmetic AST.
3. Checks each reified expression's denotation against the original expression,
   including its operations and instances. A structural precheck rejects changed
   expressions; kernel-checked equalities establish the semantic correspondence.
4. Kernel-checks the original source subterm in its original context, then the
   meaning of the **literal rendered String** and its UTF-8 encoding, using the
   source application's actual nonzero and equality proof arguments.
5. Checks the axiom inventory and emits records only after both sentences pass.

The checked declarations quantify over the original enclosing variables and
hypotheses. They do not promote a branch-local nonzero assumption into a global
fact. Changing the atom assignment, operation, conclusion, prerequisite proof,
or selected occurrence causes the corresponding negative control to fail.

The importer is a small trusted metaprogram, not a universally verified Lean
frontend. Its expression traversal, source selection, serialization implementation,
and the trusted compiler/dependency environment remain part of the operational
trust boundary. The new semantic proofs do not establish paper-to-Lean
correspondence or authenticate a potentially adversarial execution environment.

## Kernel acceptance

Certificate declarations use synchronous `Environment.addDeclCore` with kernel
checking explicitly enabled. The elaborator-level asynchronous declaration API
can defer a check and recover a failed declaration as an axiom; a record must not
be written between submission and actual acceptance. This importer requires
acceptance before proceeding, rejects unresolved metavariables and escaped local
binders, and permits only the standard axioms `propext`, `Classical.choice`, and
`Quot.sound`.

The native negative suite submits a false declaration both normally and under
`debug.skipKernelTC = true`. Both are rejected by the kernel, and neither emits
a successful certificate record. This is an executable regression for this
importer, not a security guarantee for arbitrary Lean metaprograms.

## Formal text contracts

Nine top-level contracts are required by the native gate:

| Declaration | Checked property |
| --- | --- |
| `parseTerm_chars` | Arithmetic rendering parses to the same term and preserves the suffix. |
| `parseCancellation_chars` | Sentence rendering parses to the same cancellation and preserves the suffix. |
| `readCancellation_render` | The complete String reader recovers the exact cancellation. |
| `Cancellation.render_injective` | Different represented cancellations have different rendered strings. |
| `rendered_meaning` | The rendered String has exactly the declared cancellation semantics. |
| `certify` | A cancellation law and its actual prerequisites prove that String's meaning. |
| `readBytes_render` | UTF-8 serialization and complete parsing recover the cancellation. |
| `rendered_bytes_meaning` | The emitted bytes preserve the sentence semantics. |
| `certifyBytes` | The rule and prerequisites establish the emitted bytes' meaning. |

These are universal Lean theorems over the represented fragment. They do not
certify arbitrary prose or a different implementation of the renderer. The
source-bound run instantiates them for the actual proof's variables, arithmetic,
and proof arguments. Their transitive axiom inventories contain only the three
standard axioms listed above; no admission or `sorryAx` is permitted.

`lean/ArithmeticEnglishAudit.lean` additionally contains 32 executable guards and
a kernel-checked countermodel for cancelling zero. The concrete guards are
regression executions, not independent human review or universal theorems.

## Reader integration

`proofreader/source_text.py` verifies the retained report, all file and module
hashes, all required command outcomes, and a separately pinned complete positive
record. Rehashing an altered English sentence is insufficient to make it pass.
The companion builder refuses missing or stale evidence instead of keeping a
certification label. This reader-side code does not run Lean or authenticate an
unsigned receipt.

The page inserts the two sentences verbatim as separately identified passages
in proof sections 2 and 3. It does not paraphrase certified output. HTML escaping
preserves the underlying text; static tests and real-browser tests compare the
visible text content with the native UTF-8 record. No formal theorem about HTML,
DOM behavior, browser pixels, or human interpretation is claimed.

The existing six authored proof bodies, 63 mathematical formula strings, and
86-frame source inventory remain unchanged. The full-proof English certification
flag remains false. The zero-gcd case, gcd/Bézout facts, witness construction, and
remaining polynomial calculations still need corresponding checked explanatory
representations. Two certified sentences do not certify everything in the two
sections containing them.

## Reproduce

Use a trusted Mathlib checkout at the exact revision above with dependencies
available, and Lean 4.34.1:

```sh
python scripts/check_source_cancellation.py \
  --project /path/to/pinned-mathlib \
  --lean /path/to/lean-4.34.1/bin/lean \
  --output artifacts/my-source-cancellation-run \
  --trust-project

python docs/companion/build.py
python -m pytest tests/test_source_text.py tests/test_source_cancellation_gate.py -q
PROOFREADER_REQUIRE_BROWSER=1 python -m pytest tests/reader/test_bezout_companion.py -q
```

The native gate requires a new or empty output directory separate from the
project. Its optional `--retained-environment` path is for the exact pinned
Actions archive, not an arbitrary archive claiming the same commit. New native
records must be reviewed and reconciled before updating the reader's frozen
record pin. Failed checks and unsupported cases do not increase coverage.
